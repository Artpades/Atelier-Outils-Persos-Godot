🛟_DockSystem - Effets Spéciaux et Sensations - Documentation

Module Floating Dock : une barre d'icônes qui grossissent sous le pointeur, façon dock macOS.

Godot 4.7+ Bibliothèque bin/fx 1 classe : FloatingDock Interface

📝 Présentation

Une barre de raccourcis, un sélecteur d'armes ou un menu principal gagnent en vie quand l'élément visé grossit et que ses voisins s'écartent. Les conteneurs de Godot (HBoxContainer…) ne savent pas faire déborder un élément agrandi sans décaler toute l'interface, ni animer une loupe continue qui suit le pointeur. Ce module est un conteneur qui le fait : on y place des boutons ou des icônes, ils grossissent au survol, à la souris comme au clavier et à la manette.

Pour qui ? Les intégrateurs d'interface qui veulent un menu ou une barre d'outils animés sans script.

Ce que ce module n'est pas
  • Pas un fenêtrage ni un dock d'éditeur : rien ne s'ancre, ne se détache ni ne se réordonne par glisser-déposer.
  • Pas un effet de PlayerFX : c'est un Container autonome. Pour faire grossir un seul bouton, voir 🦣 Agrandissement.

⚙️ Mode d'emploi

  1. Ajouter un FloatingDock dans l'interface et l'ancrer en bas au centre (préréglage d'ancrage Center Bottom).
    Le dock prend la taille de ses éléments au repos ; les éléments agrandis débordent vers le haut (item_anchor = End par défaut) sans pousser le reste de l'interface.
  2. Ajouter des TextureButton (ou TextureRect) comme enfants, avec ignore_texture_size et stretch_mode = Keep Aspect Centered.
    En mode RESIZE_SIZE, l'élément reçoit une taille plus grande : il faut que son image s'étire avec lui.
  3. Régler item_size, magnification et influence_radius.
    magnification est l'échelle sous le pointeur, influence_radius la distance à laquelle les voisins ne grossissent plus. L'éditeur n'affiche que l'état au repos : lancer le jeu pour voir l'effet.
  4. Facultatif : afficher le nom de l'élément survolé : 
    func _ready() -> void:
	$Dock.hovered_item_changed.connect(func(element: Control):
		$NomOutil.text = element.tooltip_text if element else "")
    hovered_item_changed est émis à chaque changement de l'élément le plus proche du pointeur, et avec null quand le pointeur quitte le dock.

💻 API Accessible

Référence générée depuis doc_classes/FloatingDock.xml. Éléments internes, non exposés : les influences par élément, les rectangles du dernier agencement, et les méthodes _get_items, _get_base_size, _get_rest_centers, _get_pointer, _layout.

📌 Exemples d'utilisation

Aperçu interactif

Reproduction dans le navigateur de l'agencement de FloatingDock (même atténuation en cosinus, même espacement) : survoler la rangée.

hovered_item_changed : —

Comment je fais un dock vertical sur le bord gauche ?

$Dock.vertical = true
$Dock.item_anchor = FloatingDock.ANCHOR_BEGIN   # collé à gauche, grossit vers la droite
$Dock.hover_lift = 8.0                           # l'élément survolé se décale vers la droite

Comment j'agrandis des boutons avec du texte ?

En mode taille, un bouton agrandi garde une police de même taille. RESIZE_SCALE met tout le rendu à l'échelle, texte compris :

$Menu.resize_mode = FloatingDock.RESIZE_SCALE
$Menu.item_size = Vector2(160, 48)
$Menu.magnification = 1.3

Comment je l'utilise à la manette ?

Avec follow_focus (actif par défaut), l'élément qui a le focus est grossi quand la souris n'est pas sur le dock. Il suffit de donner le focus au premier élément :

func ouvrir_menu() -> void:
	$Dock.get_child(0).grab_focus()

Comment je relie le dock à une barre de raccourcis ?

func _ready() -> void:
	for i in $Dock.get_child_count():
		var bouton := $Dock.get_child(i) as BaseButton
		bouton.pressed.connect(utiliser_raccourci.bind(i))

func utiliser_raccourci(index: int) -> void:
	print("Raccourci ", index)

🚧 Limitations

  • Pas d'aperçu dans l'éditeur : seul l'agencement au repos est affiché ; le grossissement n'existe qu'en jeu.
  • Débordement : les éléments agrandis sortent du rectangle du dock. Un parent qui découpe son contenu (clip_contents, ScrollContainer) les coupe ; d'autres éléments d'interface peuvent être recouverts.
  • Le survol est géométrique : la position de la souris est comparée au rectangle du dock (plus hover_margin) sans tenir compte de ce qui est dessiné par-dessus : un menu ou une fenêtre au-dessus du dock le fait quand même réagir.
  • Élément « survolé » = le plus proche du pointeur le long du dock, dans influence_radius : ce n'est pas forcément celui sous la souris (entre deux éléments, dans la marge). Les clics restent gérés par les éléments eux-mêmes.
  • get_item_influence(index) compte les enfants visibles, pas l'indice d'enfant : un enfant masqué décale les indices (les enfants masqués et top_level sont ignorés, vérifié pour la taille minimale).
  • item_size plus petit que la taille minimale d'un élément en mode RESIZE_SIZE : l'élément garde sa taille minimale et chevauche ses voisins.
  • Pause : en mode Inherit, l'animation s'arrête pendant la pause (passer le dock en Always pour un menu de pause) ; elle suit aussi Engine.time_scale.
  • Coût : chaque frame, le dock parcourt ses enfants (sans réagencer s'il n'y a pas de changement) ; négligeable pour une dizaine d'éléments.
  • Pas de tactile spécifique : sur écran tactile, le grossissement ne suit que la position de la souris émulée.

🏗️ Architecture

Composants et communication

  • FloatingDock (Container) calcule à chaque frame la position du pointeur le long du dock (souris dans la zone de survol, sinon élément qui a le focus), puis l'influence visée de chaque élément : ½ (1 + cos(π · distance / rayon)), mesurée sur l'agencement au repos.
  • Les influences sont lissées (1 − e^(−smoothing·Δt)) ; dès qu'une change, _layout recalcule tailles, espacements et positions et les applique (fit_child_in_rect ou échelle).
  • Le reste du jeu est prévenu par hovered_item_changed.

Dépendances et couplage

  • Aucune dépendance au reste du toolkit ; fonctionne avec n'importe quels enfants Control.

Décisions de conception

ChoixPourquoi (ne pas « corriger » sans en tenir compte)
Taille minimale = taille au reposLe grossissement ne doit pas redimensionner le parent : tout le reste de l'interface sauterait à chaque survol.
Influence calculée sur les positions au reposMesurée sur les positions agrandies, la loupe se déplacerait sous le pointeur et oscillerait (rétroaction).
Zone de survol élargie aux éléments agrandis + hover_marginLes éléments débordent du dock : sans cela, viser le haut d'une icône agrandie ferait retomber le dock au repos.
Lissage exponentiel indépendant du nombre d'imagesMême rendu à 30 et 144 images/s.
Deux modes, taille ou échelleLa taille garde un texte net et une mise en page correcte des boutons ; l'échelle agrandit vraiment tout le contenu (texte compris).
Suivi du focusLe même dock fonctionne au clavier et à la manette sans code supplémentaire.
