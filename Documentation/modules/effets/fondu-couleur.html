🌈_FadeSystem - Effets Spéciaux et Sensations - Documentation

Module Fondu Couleur : fondus de couleur et de texture sur un objet, et fondus de l'écran entier.

Godot 4.7+ Bibliothèque bin/fx 2 classes : FXFade · ScreenFader 2D & 3D

📝 Présentation

Faire clignoter en rouge un personnage touché, effacer un ennemi vaincu, changer l'apparence d'un objet sans « saut » brutal ou passer au noir entre deux scènes : à chaque fois, il faut écrire un Tween, mémoriser l'état d'origine, penser à le restaurer, gérer l'interruption… Ce module rend ces fondus prêts à l'emploi : on les règle dans l'inspecteur et on les déclenche d'une ligne.

🎨 FXFade — un objet

Un effet joué par un PlayerFX : fondu d'une couleur (modulate, light_color…) ou fondu enchaîné vers une autre texture, puis retour à l'état d'origine à l'arrêt.

🖥️ ScreenFader — tout l'écran

Un calque qui couvre puis découvre l'écran entier d'une couleur ou d'une image, uniformément ou en suivant la forme d'un masque (volet, iris, dissolution).

Pour qui ? Les développeurs gameplay qui scriptent des retours visuels, et les game designers qui veulent régler un fondu dans l'éditeur sans écrire de code (FXFade se prévisualise directement depuis l'inspecteur).

Ce que ce module n'est pas
  • Pas un gestionnaire de scènes : ScreenFader ne charge ni ne change de scène. Il fournit le voile ; le changement de scène reste à votre code ou au module 🎬 Gestionnaire de scènes.
  • Pas un animateur générique : seules la couleur et la texture sont fondues. Pour la taille, voir 🦣 Agrandissement ; pour la déformation, 🪗 Squash and Stretch ; pour la position, 💥 Secousse.

Mise en place

  1. Compiler le module (si les binaires ne sont pas déjà présents) depuis la racine du dépôt : 
    scons fx
    compile uniquement la bibliothèque des effets et régénère bin/fx/gameplaytoolkit_fx.gdextension ; inutile de recompiler tout le toolkit.
  2. Copier le dossier bin/fx/ dans le projet Godot, au même emplacement : res://bin/fx/.
    le fichier .gdextension référence ses binaires par des chemins absolus res://bin/fx/… ; ailleurs, Godot ne les trouve pas.
  3. Redémarrer l'éditeur après le premier ajout.
    Godot ne découvre les nouvelles extensions qu'au démarrage. Les recompilations suivantes, elles, sont rechargées à chaud (reloadable = true).
  4. Vérifier : Ajouter un nœud doit proposer PlayerFX et ScreenFader, et la ressource FXFade doit apparaître dans la liste special_effects d'un PlayerFX.
    si les classes sont absentes, la bibliothèque n'est pas chargée : consulter le panneau Sortie pour l'erreur de chargement.

Aucun autoload ni réglage de projet n'est requis. Pour les transitions entre scènes, il est toutefois recommandé de placer un ScreenFader dans un autoload (voir le mode d'emploi).

⚙️ Mode d'emploi

A. Faire flasher un objet en rouge (FXFade)

  1. Ajouter un nœud PlayerFX comme enfant du Sprite2D (ou de tout nœud ayant un modulate).
    le PlayerFX joue ses effets sur son parent par défaut et les met à jour chaque frame ; c'est lui qu'on déclenche ensuite.
  2. Dans special_effects, ajouter un élément et choisir Nouveau FXFade.
    l'effet est une ressource : il se configure dans l'inspecteur et peut être enregistré en .tres pour être réutilisé sur d'autres objets.
  3. Régler le fondu : mode = Color, color = rouge opaque, duration = 0.1.
    color_property vaut déjà modulate : c'est la propriété qui teinte le sprite. Une durée courte donne un « flash » plutôt qu'un fondu lent.
  4. Prévisualiser avec le bouton Jouer effet du PlayerFX, puis Arrêter effet.
    permet d'ajuster couleur et durée sans lancer le jeu. L'arrêt ramène la couleur d'origine (revert_on_stop).
  5. Déclencher depuis le jeu, par exemple quand le personnage est touché : 
    func _on_touche() -> void:
	$PlayerFX.play()
	await get_tree().create_timer(0.15).timeout
	$PlayerFX.stop() # retour progressif à la couleur d'origine
    play() lance le fondu vers le rouge, stop() le fondu inverse : on obtient un flash aller-retour.

B. Passer au noir entre deux scènes (ScreenFader)

  1. Créer une scène dont la racine est un ScreenFader, régler sa layer sur 100, l'enregistrer en res://fondu.tscn.
    une couche haute garantit que le voile passe au-dessus de toute l'interface du jeu.
  2. Déclarer cette scène en autoload sous le nom Fondu (Projet › Paramètres du projet › Globals).
    un autoload n'est pas détruit lors d'un changement de scène : le voile reste en place pendant que la scène suivante se charge.
  3. Encadrer le changement de scène par un fondu sortant et un fondu entrant : 
    func aller_a(chemin: String) -> void:
	Fondu.fade_out()          # l'écran se couvre en 0,5 s (duration)
	await Fondu.faded_out     # attendre qu'il soit entièrement noir
	get_tree().change_scene_to_file(chemin)
	Fondu.fade_in()           # l'écran se découvre sur la nouvelle scène
    le changement de scène se fait pendant que l'écran est couvert : le joueur ne voit ni la disparition de l'ancienne scène ni l'apparition de la nouvelle.

💻 API Accessible

Référence générée depuis doc_classes/FXFade.xml et doc_classes/ScreenFader.xml. Seuls les éléments exposés à Godot figurent ici ; le reste est interne et peut changer sans préavis :

  • FXFade : l'état du fondu (couleur et texture d'origine, Tween courant), le matériau de fondu enchaîné, et les méthodes _fade_color_to, _fade_texture_to, _finish_crossfade, _new_tween.
  • ScreenFader : le ColorRect interne FadeOverlay (non visible dans l'arbre de scène, non enregistré) et son ShaderMaterial.
  • Les méthodes héritées play_fx, stop_fx… de Effect sont documentées avec le module ✨ Socle des effets ; cochez « membres hérités » pour les afficher ici.

📌 Exemples d'utilisation

Aperçu interactif du ScreenFader

Reproduction dans le navigateur du shader de ScreenFader : même calcul de recouvrement (smoothstep(m, m + smoothness, progress × (1 + smoothness))), mêmes courbes de transition.

Signal : —

Comment je fais disparaître un ennemi vaincu, puis le supprime ?

FXFade n'émet pas de signal de fin de fondu : on attend sa duration. revert_on_stop = false évite toute réapparition si l'effet est arrêté entre-temps.

func mourir() -> void:
	var effacement := FXFade.new()
	effacement.color = Color(1, 1, 1, 0)   # blanc transparent : l'ennemi s'efface
	effacement.duration = 0.6
	effacement.revert_on_stop = false
	$PlayerFX.special_effects = [effacement]
	$PlayerFX.play()
	set_physics_process(false)             # plus d'IA pendant l'effacement
	await get_tree().create_timer(effacement.duration).timeout
	queue_free()

Comment je change l'apparence d'un objet en douceur (fondu enchaîné) ?

En mode texture sur un Sprite2D ou un TextureRect, les deux images sont réellement mélangées. Idéal pour un objet qui s'abîme, un portrait qui change d'expression, une saison qui passe…

@export var porte_ouverte: Texture2D

func ouvrir() -> void:
	var fondu := FXFade.new()
	fondu.mode = FXFade.FADE_TEXTURE
	fondu.texture = porte_ouverte
	fondu.duration = 0.4
	fondu.revert_on_stop = false    # la porte reste ouverte
	$PlayerFX.special_effects = [fondu]
	$PlayerFX.play()

Comment je fais varier la couleur d'une lumière ou d'un matériau 3D ?

color_property accepte n'importe quelle propriété Color, y compris dans une sous-ressource. Ici, une lampe d'alarme qui passe au rouge tant que l'alarme est active.

# PlayerFX enfant d'une OmniLight3D
func _ready() -> void:
	var alarme := FXFade.new()
	alarme.color_property = "light_color"
	alarme.color = Color.RED
	alarme.duration = 1.0
	$PlayerFX.special_effects = [alarme]

func set_alarme(active: bool) -> void:
	if active:
		$PlayerFX.play()
	else:
		$PlayerFX.stop()  # retour à la couleur d'origine de la lampe

# Sur un MeshInstance3D avec un StandardMaterial3D en material_override :
# alarme.color_property = "material_override:albedo_color"

Comment je combine le fondu avec d'autres effets ?

Tout Effect peut en entraîner d'autres : effects_on_play_fx sont joués et arrêtés avec lui, effects_on_stop_fx sont joués à son arrêt.

var flash := FXFade.new()
flash.color = Color(2, 2, 2)            # surexposé : flash blanc lumineux
flash.duration = 0.05
flash.effects_on_play_fx = [FXShake.new()]   # secousse en même temps que le flash
$PlayerFX.special_effects = [flash]
$PlayerFX.play()

Comment je fais une transition en iris ou en volet ?

Le mask est une image en niveaux de gris : le noir est couvert en premier, le blanc en dernier. Un GradientTexture2D radial suffit pour un iris ; pour un volet, un dégradé linéaire.

func _ready() -> void:
	var degrade := Gradient.new()
	degrade.colors = PackedColorArray([Color.WHITE, Color.BLACK])  # centre blanc, bords noirs
	var iris := GradientTexture2D.new()
	iris.gradient = degrade
	iris.fill = GradientTexture2D.FILL_RADIAL
	iris.fill_from = Vector2(0.5, 0.5)
	iris.fill_to = Vector2(1.0, 0.5)
	Fondu.mask = iris              # les bords se ferment d'abord, le centre en dernier
	Fondu.mask_smoothness = 0.05   # bord net

Comment j'assombris l'écran derrière un menu de pause ?

fade_to vise un recouvrement partiel. always_process (actif par défaut) laisse le fondu tourner alors que le jeu est en pause.

func ouvrir_pause() -> void:
	get_tree().paused = true
	Fondu.block_input = false   # le menu de pause doit rester cliquable
	Fondu.fade_to(0.6, 0.2)     # voile noir à 60 %
	$MenuPause.show()           # CanvasLayer plus haut que Fondu.layer

func fermer_pause() -> void:
	$MenuPause.hide()
	Fondu.fade_in(0.2)
	await Fondu.faded_in
	Fondu.block_input = true
	get_tree().paused = false

Comment j'attends un fondu sans risquer de bloquer ?

Si le fondu est instantané (durée nulle, ou écran déjà couvert avec une durée nulle), le signal est émis avant le await qui l'attend. Tester l'état d'abord :

func couvrir(duree := -1.0) -> void:
	Fondu.fade_out(duree)
	if not Fondu.is_covered():
		await Fondu.faded_out

🚧 Limitations

FXFade

  • Aucun signal de fin de fondu. fx_played est émis au début du fondu. Pour enchaîner une action à la fin, attendre duration secondes (voir exemple).
  • Un effet = une cible à la fois. L'état d'origine (couleur, texture, Tween) est stocké dans la ressource. Jouer la même instance de FXFade sur deux cibles simultanément (via PlayerFX.play(autre_noeud), ou en partageant une ressource créée par code) mélange leurs états : la première cible ne revient pas à sa couleur. Les ressources enregistrées dans une scène sont dupliquées par instance (resource_local_to_scene), ce qui protège le cas courant.
  • L'état d'origine est capturé au premier play(). Si un autre système change la couleur de la cible pendant l'effet, l'arrêt la ramène quand même à l'ancienne valeur.
  • Le fondu suit la pause et Engine.time_scale de la cible. Le Tween appartient au nœud cible : il se fige en pause (sauf si la cible a process_mode = ALWAYS) et ralentit avec un ralenti global.
  • Propriété introuvable = effet ignoré. Si color_property ne désigne pas une Color sur la cible, un avertissement [FXFade] est écrit et rien ne se passe ; aucune erreur n'est levée.
  • Mode texture sur un CanvasItem : le material de la cible est remplacé pendant le fondu par le shader de mélange, puis restauré. Un shader personnalisé (contour, dissolution…) disparaît donc le temps du fondu, et un matériau assigné par un autre script pendant ce temps est écrasé à la fin.
  • Mode texture : les deux textures sont lues avec les mêmes UV. Avec une feuille de sprites (hframes, region) ou des tailles différentes, l'image intermédiaire n'est cohérente que si les deux textures ont la même disposition.
  • Mode texture hors CanvasItem (Sprite3D…) : pas de vrai mélange, la cible s'efface, change de texture et réapparaît. Sans propriété modulate (texture d'un matériau 3D…), le changement est instantané.
  • Pas de fondu si la cible n'est pas dans l'arbre ou si duration ≤ 0 : la valeur finale est appliquée immédiatement.
  • Prévisualisation dans l'éditeur : enregistrer la scène pendant que l'effet est joué enregistre la couleur ou la texture modifiée. Arrêter l'effet avant de sauvegarder.

ScreenFader

  • block_input ne bloque que la souris et le tactile (filtre souris d'un Control). Le clavier et la manette passent toujours : désactiver soi-même les actions du joueur pendant une transition si nécessaire.
  • Un fondu interrompu n'émet aucun signal. Si fade_in() est appelé pendant un fade_out(), le await faded_out en attente ne se terminera jamais.
  • Fondu instantané = signaux synchrones. Avec une durée nulle (ou hors de l'arbre), les signaux sont émis pendant l'appel, avant tout await placé après (voir exemple).
  • Couvre uniquement son viewport. En écran partagé (plusieurs SubViewport), il faut un ScreenFader par viewport ; et tout CanvasLayer de layer supérieure reste visible au-dessus du voile.
  • La texture est étirée sur tout l'écran, sans conserver ses proportions ; le masque n'utilise que le canal rouge.
  • always_process n'est pris en compte qu'au fondu suivant, pas sur un fondu déjà lancé.
  • Pas de file d'attente : chaque appel remplace le fondu en cours (il repart de la valeur actuelle de progress).

🏗️ Architecture

Composants et communication

  • FXFade est une ressource dérivée de Effect. Le PlayerFX l'appelle directement (play_fx → _play, stop_fx → _stop) ; aucun signal n'est utilisé entre eux. L'animation est un Tween créé sur la cible, avec ses réglages transition / ease_type.
  • En mode texture sur un CanvasItem, un ShaderMaterial (créé une fois, puis gardé en cache dans la ressource) remplace temporairement le material de la cible. Le Tween anime son paramètre progress, puis un rappel final pose la nouvelle texture et restaure le matériau d'origine.
  • ScreenFader est un CanvasLayer autonome. À l'entrée dans l'arbre, il crée un ColorRect plein écran interne portant un ShaderMaterial. Toute modification d'un réglage recopie les valeurs dans le shader. Les fondus animent la propriété progress du nœud lui-même et signalent leur fin par fade_finished, puis faded_out / faded_in.

Dépendances et couplage

  • FXFade → Effect (héritage) : même bibliothèque fx, couplage fort mais interne.
  • ScreenFader ne dépend d'aucune autre classe du toolkit, et FXFade et ScreenFader s'ignorent mutuellement.
  • Le module est compilé dans sa propre bibliothèque (fx_register.cpp → bin/fx/). Un autre module ne doit pas inclure ses .hpp : il passe par Godot (ClassDB.instantiate("ScreenFader"), call("fade_out")…).

Décisions de conception

ChoixPourquoi (ne pas « corriger » sans en tenir compte)
Le Tween de FXFade est créé sur la cible, pas sur le PlayerFXIl est automatiquement détruit si la cible est libérée : pas d'animation qui viserait un nœud supprimé.
L'état d'origine n'est pas recapturé quand l'effet est relancé (_is_restarting())Pendant un fondu, la cible est déjà modifiée : la recapturer ferait « oublier » la vraie couleur d'origine, et l'arrêt ne reviendrait plus à l'état initial.
Mélange par shader sur CanvasItem, effacement / réapparition ailleursLe shader donne un vrai fondu enchaîné sans dupliquer le nœud. Les nœuds 3D n'ont pas de point d'injection aussi universel : le repli par modulate marche partout où il existe.
progress est une propriété, pas seulement une méthodeElle peut être animée par un AnimationPlayer ou réglée directement, pour des transitions synchronisées sur une cinématique.
FadeOverlay est un enfant interneIl n'apparaît pas dans l'arbre de scène et n'est pas enregistré dans le .tscn : impossible de le supprimer ou de le dupliquer par erreur.
Voile masqué à progress = 0Aucun coût de rendu (fill-rate) quand l'écran est découvert, ce qui est le cas 99 % du temps.
always_process et block_input actifs par défautLes transitions partent souvent d'un menu de pause ou d'un ralenti ; et un clic pendant un fondu de changement de scène déclencherait une action sur une scène en train de disparaître.
Code des shaders en ASCII uniquementLes chaînes const char * sont lues en Latin-1 par godot-cpp : un accent dans un commentaire du shader casserait sa compilation.
