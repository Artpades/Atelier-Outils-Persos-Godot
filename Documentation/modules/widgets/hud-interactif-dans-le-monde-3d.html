🖥️_SpatialHUDSystem - Widgets & Spatialité - Documentation

Module HUD interactif dans le monde 3D : afficher une interface Godot (boutons, curseurs, champs de texte) sur un panneau de la scène 3D, et l'utiliser au curseur, au viseur ou au laser.

Godot 4.7+ Bibliothèque bin/spatial_hud 1 classe : InteractiveHUD3D 3D · souris, viseur, VR

📝 Présentation

Un terminal d'ordinateur dans un jeu à la première personne, un distributeur dont on presse les boutons, un écran de contrôle dans un cockpit, un menu flottant en réalité virtuelle : l'interface doit faire partie du décor 3D et rester cliquable. Godot sait afficher un SubViewport sur un maillage, mais il faut ensuite projeter le pointeur sur le panneau, convertir le point touché en pixels, renvoyer les évènements souris, gérer le survol, le glisser au-delà du bord, le clavier, les panneaux superposés… Ce nœud fait tout cela : on lui donne une scène d'interface ordinaire, elle devient un panneau 3D utilisable.

Pour qui ? Les développeurs de jeux 3D (FPS, simulation, VR) et les intégrateurs d'interface qui veulent réutiliser leurs scènes Control telles quelles dans le monde.

Ce que ce module n'est pas
  • Pas un HUD d'écran : pour une interface collée à l'écran, un CanvasLayer suffit. Ici, le panneau est un objet du monde, avec une position, une taille en mètres et une perspective.
  • Pas une étiquette flottante : pour un simple texte au-dessus d'un personnage, un Label3D est plus léger (pas de SubViewport).
  • Pas un système d'interaction physique : il ne gère que le pointeur sur le panneau, pas la saisie d'objets (voir ✊ Glisser-Déposer d'objet).

Mise en place

  1. Compiler (si besoin) : 
    scons spatial_hud
    compile la bibliothèque du registre spatial_hud_register.cpp.
  2. Copier bin/spatial_hud/ dans res://bin/ et redémarrer l'éditeur.
    chemins res://bin/spatial_hud/… absolus ; extensions découvertes au démarrage.

Le nœud fonctionne aussi dans l'éditeur pour l'affichage (le contenu est visible dans la vue 3D) ; l'interaction, elle, n'est active qu'en jeu.

⚙️ Mode d'emploi

  1. Créer la scène d'interface terminal_ui.tscn : un Panel racine avec un Button nommé Valider (cocher Accès en tant que nom unique).
    c'est une scène Control ordinaire, testable seule ; elle sera étirée sur tout le panneau.
  2. Dans la scène 3D, ajouter un InteractiveHUD3D et régler content_scene = terminal_ui.tscn.
    le nœud crée lui-même le SubViewport et le quad, en enfants internes : rien d'autre à ajouter dans l'arbre.
  3. Régler la taille : viewport_size = résolution de l'interface (512 × 320 px par défaut), pixel_size = mètres par pixel (0,0025 : panneau de 1,28 × 0,8 m).
    la résolution règle la netteté, pixel_size la taille dans le monde ; les deux sont indépendants.
  4. Réagir au bouton : 
    func _ready() -> void:
	$InteractiveHUD3D.get_content().get_node("%Valider").pressed.connect(_ouvrir_porte)
    get_content() renvoie l'instance de la scène d'interface : ses signaux se connectent comme d'habitude.
  5. Lancer : avec la souris libre, survoler et cliquer le panneau. Pour un FPS à souris capturée, régler pointer_source = Screen Center.
    en Screen Center, c'est le centre de l'écran (le viseur) qui pointe ; les clics de la souris restent utilisés.

💻 API Accessible

Référence générée depuis doc_classes/InteractiveHUD3D.xml. Éléments internes, non exposés : les enfants internes HUDViewport (SubViewport) et HUDQuad (MeshInstance3D avec QuadMesh et StandardMaterial3D) — accessibles en lecture par get_sub_viewport() mais à ne pas restructurer —, le groupe interne _interactive_hud_3d qui sert à départager les panneaux, l'état de capture des boutons, et les méthodes _intersect, _hit, _is_occluded, _is_behind_another_hud, _forward_mouse…

📌 Exemples d'utilisation

Comment j'utilise un laser de manette VR (ou un pointeur de manette) ?

En mode Manual, on fournit le rayon et les appuis ; chaque panneau manuel a son propre rayon.

@onready var hud: InteractiveHUD3D = $Menu   # pointer_source = Manual

func _process(_delta: float) -> void:
	var main: Node3D = $XROrigin3D/MainDroite
	hud.set_pointer_ray(main.global_position, -main.global_basis.z)

func _on_gachette_pressee() -> void:
	hud.press_pointer()

func _on_gachette_relachee() -> void:
	hud.release_pointer()

Comment je dessine le laser jusqu'au point visé ?

ray_to_hud donne le pixel touché, hud_to_world le ramène dans le monde.

func longueur_laser(origine: Vector3, direction: Vector3) -> float:
	var pixel = $Menu.ray_to_hud(origine, direction)
	if pixel == null:
		return 5.0   # rien touché : laser de 5 m
	return origine.distance_to($Menu.hud_to_world(pixel))

Comment je n'autorise l'interaction qu'à proximité ?

func _ready() -> void:
	$Terminal.max_distance = 2.0           # au-delà de 2 m, le panneau ignore le pointeur
	$Terminal.check_occlusion = true       # un mur entre le joueur et l'écran le masque
	$Terminal.pointer_entered.connect(func(): $Indication.show())
	$Terminal.pointer_exited.connect(func(): $Indication.hide())

Comment je saisis du texte sur un panneau (code de porte) ?

Un clic sur le panneau lui donne le focus clavier ; les touches lui sont envoyées tant qu'un de ses Control a le focus. Couper les déplacements du joueur pendant la saisie :

func _process(_delta: float) -> void:
	$Joueur.controles_actifs = not $Terminal.is_focused()

Comment je fais une étiquette interactive qui fait toujours face au joueur ?

var info := InteractiveHUD3D.new()
info.content_scene = preload("res://ui/fiche_objet.tscn")
info.viewport_size = Vector2i(300, 120)
info.billboard = InteractiveHUD3D.BILLBOARD_Y   # tourne seulement autour de l'axe vertical
info.always_on_top = true                       # jamais caché par le décor
info.position = Vector3(0, 1.5, 0)
$Coffre.add_child(info)

Comment je change le contenu du panneau (pages d'un menu) ?

func afficher_page(scene: PackedScene) -> void:
	$Menu.set_content(scene.instantiate())   # l'ancienne page est libérée

🚧 Limitations

  • Coût de rendu : chaque panneau rend son SubViewport à chaque image (UPDATE_ALWAYS), même immobile ou hors champ. Une dizaine de panneaux 1024 px se ressent sur mobile ; passer get_sub_viewport().render_target_update_mode en When Visible ou Once pour les panneaux statiques.
  • Coût de l'interaction : chaque panneau recalcule son survol à chaque image et compare son rayon à tous les autres panneaux de même source (coût quadratique) : à éviter au-delà de quelques dizaines de panneaux interactifs.
  • Priorité de l'interface d'écran : appuis et mouvements passent par _unhandled_input ; un Control plein écran en MOUSE_FILTER_STOP (même transparent) bloque tous les panneaux.
  • Occlusion physique seulement : check_occlusion teste les collisions (calques occlusion_mask), pas l'image. Un décor sans collision ne cache pas le panneau pour le pointeur ; il est désactivé par défaut, donc le panneau est cliquable à travers les murs.
  • Une caméra, un Viewport : les sources Mouse / Screen Center utilisent la caméra courante du Viewport du panneau ; en écran partagé, un seul joueur peut pointer (sauf en Manual).
  • Clavier seulement : les évènements clavier sont renvoyés au panneau qui a le focus ; la navigation à la manette (ui_accept, flèches) dans le panneau n'est pas prise en charge sans pointeur.
  • Souris capturée en mode Mouse : la position du curseur ne change plus ; utiliser Screen Center.
  • Lisibilité : texture filtrée linéairement sans mipmaps ; de loin ou en biais, le texte crénelé scintille. Augmenter viewport_size et réduire pixel_size d'autant.
  • Transparence : transparent_background (actif par défaut) rend le matériau transparent, avec les problèmes de tri habituels de Godot (panneau qui passe derrière des particules, des vitres…). Le désactiver pour un écran opaque.

🏗️ Architecture

Composants et communication

  • À l'entrée dans l'arbre, InteractiveHUD3D crée un SubViewport et un quad en enfants internes (jamais sauvegardés), instancie content_scene dans le SubViewport et applique sa texture au quad.
  • À chaque image et à chaque évènement souris, le rayon du pointeur est ramené dans le repère du quad ; le point touché devient un pixel. Les évènements souris sont recopiés à cette position et envoyés au SubViewport par push_input ; le survol est signalé au SubViewport comme le ferait un SubViewportContainer.
  • Plusieurs panneaux se départagent par un groupe interne : seul le plus proche (ou celui qui a capturé un bouton) traite le pointeur. Le code du jeu reçoit les signaux pointer_* et ceux de sa propre interface.

Dépendances et couplage

  • Aucune dépendance vers les autres modules ; aucun module n'en dépend. Bibliothèque propre : spatial_hud_register.cpp → bin/spatial_hud/.
  • Le contenu n'a aucun lien avec le panneau : n'importe quelle scène Control fonctionne, sans script particulier.

Décisions de conception

ChoixPourquoi (ne pas « corriger » sans en tenir compte)
SubViewport et quad créés par le nœud, en enfants internesUn seul nœud à ajouter ; rien ne peut être supprimé ou dupliqué par erreur, et rien n'est enregistré dans le .tscn.
Intersection mathématique rayon / plan, pas de CollisionShape3DPas de calque physique à réserver, et le pixel touché est exact (pas de forme de collision à synchroniser avec la taille du panneau).
Appuis par _unhandled_input, relâchements par _inputL'interface d'écran garde la priorité, mais un relâchement n'est jamais perdu (sinon un curseur resterait « collé »).
Capture des boutonsGlisser un curseur au-delà du bord du panneau doit continuer à le faire bouger, comme à l'écran.
Clavier renvoyé seulement si un Control du panneau a le focusSinon, chaque touche du joueur (déplacement) serait volée par le panneau cliqué.
Survol réévalué à chaque imageLa caméra ou le panneau peuvent bouger sous un pointeur immobile (FPS, véhicule).
Mouvement « hors du viewport » envoyé à la sortieNOTIFICATION_VP_MOUSE_EXIT seul ne retire pas le survol des Control : un bouton resterait en surbrillance.
