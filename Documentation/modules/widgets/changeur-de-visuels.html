🎭_VisualsSystem - Widgets & Spatialité - Documentation

Module Changeur de Visuels : changer d'un appel l'apparence d'un personnage ou d'un objet (tenue, skin, transformation), décrite dans des ressources.

Godot 4.7+ Bibliothèque bin/visuals_swapper 3 classes : VisualsSwapper · VisualsAsset · VisualsRegister 2D, 3D & interface

📝 Présentation

Un héros qui ramasse une fleur de feu change de couleur, de chapeau et d'arme ; un client choisit une skin dans la boutique ; un bâtiment évolue de niveau. Écrit à la main, chaque changement devient une suite de $Corps.texture = …, $Arme.mesh = … éparpillée dans les scripts. Ce module décrit chaque apparence dans une ressource (quels nœuds changent, et en quoi) et l'applique d'un appel, par son nom.

🎭 VisualsSwapper — le nœud

Placé dans la scène, il contient le catalogue des apparences et les applique (swap_by_name("feu")).

👕 VisualsAsset — une apparence

Une ressource nommée regroupant tous les changements d'une tenue ; réutilisable entre scènes.

🔧 VisualsRegister — un changement

Un nœud cible et sa nouvelle texture, son nouveau maillage ou sa nouvelle scène.

Pour qui ? Les artistes et game designers qui préparent des variantes visuelles dans l'inspecteur, et les développeurs qui veulent les déclencher sans connaître la structure de la scène.

Ce que ce module n'est pas
  • Pas un fondu ni une animation : le changement est instantané. Pour un passage progressif d'une texture à l'autre, voir FXFade en mode texture (🌈 Fondu Couleur).
  • Pas un système d'équipement : il ne gère ni inventaire ni statistiques, uniquement l'apparence.
  • Pas réversible tout seul : l'apparence d'origine n'est pas mémorisée ; on la décrit comme une apparence « normal ».
📷 Image à insérer
Capture de l'inspecteur d'un VisualsSwapper déplié (trois VisualsAsset « normal », « feu », « glace », l'un ouvert sur ses VisualsRegister), à côté du personnage dans les trois apparences.

Mise en place

  1. Compiler (si besoin) : 
    scons visuals_swapper
    compile la bibliothèque du registre visuals_swapper_register.cpp.
  2. Copier bin/visuals_swapper/ dans res://bin/ et redémarrer l'éditeur.
    chemins res://bin/visuals_swapper/… absolus ; extensions découvertes au démarrage.

Contrairement à d'autres modules, ces classes fonctionnent aussi dans l'éditeur (un @tool peut appeler swap pour prévisualiser).

⚙️ Mode d'emploi

  1. Ajouter un nœud VisualsSwapper comme enfant du personnage, à côté de son Sprite2D nommé Corps.
    les chemins des changements sont résolus depuis ce nœud : ../Corps désignera le sprite.
  2. Dans visuals_assets, ajouter un Nouveau VisualsAsset et régler suit_type_name = feu.
    ce nom sert à retrouver l'apparence par code ; l'asset peut être enregistré en .tres pour d'autres personnages.
  3. Dans ses visuals_registers, ajouter un Nouveau VisualsRegister : node_visual = ../Corps, texture = l'image du corps en feu.
    le nœud ciblé étant un Sprite2D, seule la texture est utilisée.
  4. Répéter pour une apparence normal avec la texture d'origine.
    c'est elle qui permettra de revenir en arrière : rien n'est mémorisé automatiquement.
  5. Déclencher : 
    func _on_fleur_de_feu_ramassee() -> void:
	$VisualsSwapper.swap_by_name("feu")

func _on_degats() -> void:
	$VisualsSwapper.swap_by_name("normal")
    swap_by_name cherche dans le catalogue ; un nom inconnu ne fait rien.

💻 API Accessible

Référence générée depuis doc_classes/VisualsSwapper.xml, VisualsAsset.xml et VisualsRegister.xml. Le module n'a pas d'élément interne notable : toute la logique est dans VisualsAsset.swap_visuals, exposée.

📌 Exemples d'utilisation

Comment je change le modèle 3D complet d'un personnage ?

Un Node3D « conteneur » n'est ni à texture ni à maillage : ses enfants sont remplacés par la scène modeling_import (un .glb importé, par exemple).

# Joueur
# ├─ VisualsSwapper
# └─ Modele (Node3D) ← contient le modèle actuel
var robot := VisualsRegister.new()
robot.node_visual = ^"../Modele"
robot.modeling_import = preload("res://modeles/robot.glb")
var tenue := VisualsAsset.new()
tenue.suit_type_name = "robot"
tenue.visuals_registers = [robot]
$VisualsSwapper.swap(tenue)

Les anciens enfants sont libérés à la fin de l'image (queue_free) : pendant l'image du changement, ancien et nouveau modèle coexistent. Toute référence vers l'ancien modèle (un AnimationPlayer, un Skeleton3D) doit être recherchée à nouveau.

Comment je propose des skins dans une boutique ?

Chaque skin est un .tres ; la boutique liste le catalogue et le nom choisi est sauvegardé.

func remplir_boutique() -> void:
	for skin: VisualsAsset in $Joueur/VisualsSwapper.visuals_assets:
		var bouton := Button.new()
		bouton.text = skin.suit_type_name.capitalize()
		bouton.pressed.connect(func():
			$Joueur/VisualsSwapper.swap(skin)
			Sauvegarde.skin = skin.suit_type_name)
		$Liste.add_child(bouton)

func _ready() -> void:
	$Joueur/VisualsSwapper.swap_by_name(Sauvegarde.skin)

Comment je change les icônes d'une interface selon la saison ?

TextureRect est pris en charge ; un même VisualsAsset peut viser plusieurs nœuds.

func appliquer_saison(saison: String) -> void:
	var asset: VisualsAsset = load("res://saisons/%s.tres" % saison)
	asset.apply($HUD)   # chemins résolus depuis $HUD (« Fond », « Icone/Soleil »…)

Comment je change d'apparence avec un flash ?

Combiné au module 🌈 Fondu Couleur : un flash blanc masque le changement instantané.

func transformer(nom: String) -> void:
	var flash := FXFade.new()
	flash.color = Color(3, 3, 3)
	flash.duration = 0.08
	$PlayerFX.special_effects = [flash]
	$PlayerFX.play()
	await get_tree().create_timer(0.08).timeout
	$VisualsSwapper.swap_by_name(nom)
	$PlayerFX.stop()

🚧 Limitations

  • Types reconnus limités : texture pour Sprite2D, Sprite3D, Polygon2D, TextureRect ; maillage pour MeshInstance2D / MeshInstance3D. Un AnimatedSprite2D, un TextureButton, un NinePatchRect, un matériau… ne reçoivent pas la texture : ils sont traités comme conteneurs (vérifié avec AnimatedSprite2D : texture ignorée ; avec une scène, ses enfants sont remplacés). Pour les SpriteFrames, passer par modeling_import ou par code.
  • Échecs silencieux : chemin introuvable, ressource absente, nom inconnu dans swap_by_name — rien ne se passe et aucun message n'est écrit.
  • Aucun signal, aucun retour arrière : l'apparence d'origine n'est pas mémorisée ; prévoir un asset « normal ».
  • Réglages annexes inchangés : hframes, region_rect, offset d'un sprite, matériaux surchargés d'un maillage. Une nouvelle texture de dimensions différentes peut donc être mal découpée.
  • Remplacement de scène : tous les enfants du conteneur sont libérés (même ceux qui ne faisaient pas partie du modèle), libération différée (ancien et nouveau coexistent une image), et la nouvelle instance n'a pas de propriétaire (elle n'est pas enregistrée si la scène est sauvegardée depuis un outil d'éditeur).
  • Pas de fondu : changement instantané (voir l'exemple).

🏗️ Architecture

Composants et communication

  • VisualsSwapper ne fait que choisir l'asset et se passer lui-même comme contexte de résolution des chemins.
  • VisualsAsset parcourt ses registres et appelle la méthode statique swap_visuals, qui teste le type du nœud ciblé et lui donne la ressource adaptée.
  • VisualsRegister est une donnée passive. Tous les appels sont directs et synchrones ; aucun signal.

Dépendances et couplage

  • Aucune dépendance vers d'autres modules ; aucun module n'en dépend. Bibliothèque propre : visuals_swapper_register.cpp → bin/visuals_swapper/.

Décisions de conception

ChoixPourquoi (ne pas « corriger » sans en tenir compte)
Apparences décrites dans des ressourcesElles se préparent dans l'inspecteur, se partagent entre scènes (.tres) et se chargent à la demande (boutique, DLC).
Chemins résolus depuis un nœud de contexteLe même asset sert pour toutes les instances d'un personnage : il ne contient aucune référence à une instance précise.
Type du nœud détecté automatiquementUn seul type de registre pour la 2D, la 3D et l'interface ; seule la ressource utile est lue.
swap_visuals statiqueUtilisable sans VisualsSwapper ni VisualsAsset, pour un changement ponctuel par code.
Anciens enfants libérés par queue_freeLe changement peut être déclenché par un signal émis par l'un de ces enfants : le libérer immédiatement ferait planter l'émetteur.
