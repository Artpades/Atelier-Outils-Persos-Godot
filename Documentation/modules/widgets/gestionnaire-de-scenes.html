Module Gestionnaire de scènes : charger le niveau suivant en arrière-plan, afficher sa progression, puis l'ouvrir.

Godot 4.7+ Bibliothèque bin/scene_manager 1 classe : SceneManager

📝 Présentation

get_tree().change_scene_to_file() charge la scène suivante pendant l'image : sur un gros niveau, le jeu se fige plusieurs secondes sans rien afficher. Le chargement en arrière-plan de Godot (ResourceLoader.load_threaded_request) règle ce problème, mais demande de sonder son état à chaque image, de récupérer la ressource et d'enchaîner le changement de scène. Ce module le fait en un appel et prévient par des signaux : démarrage, progression, scène prête.

Pour qui ? Les développeurs qui écrivent les menus, les écrans de chargement et les passages d'un niveau à l'autre.

Ce que ce module n'est pas
  • Pas un système de transition visuelle : aucun fondu n'est affiché. Le combiner avec ScreenFader du module 🌈 Fondu Couleur (voir l'exemple).
  • Pas un gestionnaire de pile de scènes : pas d'historique, pas de scènes additives, pas de retour arrière ; il remplace la scène courante, comme change_scene_to_packed.
  • Pas un préchargeur : la scène chargée est toujours ouverte aussitôt.

Mise en place

  1. Compiler le module (si besoin) : 
    scons scene_manager
    Compile la bibliothèque du registre scene_manager_register.cpp.
  2. Copier bin/scene_manager/ dans res://bin/ et redémarrer l'éditeur.
    Chemins res://bin/scene_manager/… absolus dans le .gdextension ; découverte des extensions au démarrage.
  3. Rendre le gestionnaire persistant : soit l'obtenir par SceneManager.get_instance() (avec ManagerBuilder, il est créé sous la racine de l'arbre), soit déclarer en autoload une scène dont la racine est un SceneManager.
    Le gestionnaire doit survivre au changement de scène pour émettre load_finished : placé dans la scène qui va être remplacée, il serait détruit avant.

⚙️ Mode d'emploi

  1. Depuis le menu principal, lancer le chargement : 
    func _on_jouer_pressed() -> void:
	SceneManager.get_instance().load_scene_async("res://niveaux/niveau_1.tscn")
    Le niveau se charge sur un autre fil d'exécution ; le menu reste affiché et animé pendant ce temps.
  2. Afficher la progression dans une ProgressBar du menu : 
    func _ready() -> void:
	SceneManager.get_instance().loading_progress.connect(func(p): $Barre.value = p)
    loading_progress donne un pourcentage (0 à 100) à chaque image du chargement.
  3. Rien d'autre à faire : une fois chargé, le niveau remplace la scène courante, puis load_finished est émis.
    Le changement de scène est différé à la fin de l'image pour ne pas détruire la scène courante au milieu de son traitement.

💻 API Accessible

Référence générée depuis doc_classes/SceneManager.xml. Éléments internes, non exposés : le chemin en cours de chargement, l'indicateur « changement de scène attendu » (qui distingue un changement demandé par le gestionnaire d'un change_scene_to_file fait ailleurs), et les méthodes _finish_loading, _on_scene_changed, _log.

📌 Exemples d'utilisation

Comment je fais un écran de chargement réutilisable ?

Un autoload Chargement (un CanvasLayer avec une barre) qui reste affiché pendant le changement de scène :

# chargement.gd — racine de la scène autoload « Chargement »
extends CanvasLayer

func _ready() -> void:
	hide()
	var scenes := SceneManager.get_instance()
	scenes.loading_started.connect(show)
	scenes.loading_progress.connect(func(p): $Barre.value = p)
	scenes.load_finished.connect(hide)

func aller_a(chemin: String) -> void:
	SceneManager.get_instance().load_scene_async(chemin)

Comment je combine le chargement avec un fondu au noir ?

Avec un autoload Fondu (un ScreenFader, module 🌈 Fondu Couleur) : couvrir l'écran, charger, découvrir.

func changer_de_niveau(chemin: String) -> void:
	var scenes := SceneManager.get_instance()
	if scenes.is_loading():
		return
	Fondu.fade_out()
	await Fondu.faded_out
	scenes.load_scene_async(chemin)
	await scenes.load_finished
	Fondu.fade_in()

Comment je détecte un échec de chargement ?

Aucun signal n'est émis en cas d'échec : is_loading() repasse à false sans load_finished. On peut le surveiller, et vérifier le chemin avant :

func charger_en_securite(chemin: String) -> void:
	if not ResourceLoader.exists(chemin, "PackedScene"):
		push_error("Scène introuvable : " + chemin)
		return
	var scenes := SceneManager.get_instance()
	scenes.load_scene_async(chemin)
	while scenes.is_loading():
		await get_tree().process_frame
	await get_tree().process_frame   # laisser le changement différé s'appliquer
	if get_tree().current_scene.scene_file_path != chemin:
		push_error("Échec du chargement : " + chemin)

Comment je suis un chargement dans la console ?

SceneManager.get_instance().log_activated = true
# 🚀 Chargement asynchrone démarré… ⏳ Progression : 42.0% … ✅ Chargement terminé !

🚧 Limitations

  • Aucun signal d'échec (vérifié avec un chemin inexistant : loading_started, quelques loading_progress(0), puis plus rien). Un await load_finished reste bloqué indéfiniment ; un écran de chargement reste affiché. Voir l'exemple.
  • Erreurs silencieuses par défaut : les messages du gestionnaire (chemin vide, requête refusée, échec) ne sont écrits que si log_activated est actif. Godot affiche toutefois ses propres erreurs de chargement.
  • Un chargement à la fois, et les demandes suivantes sont ignorées sans retour (vérifié). Tester is_loading() avant.
  • Pas d'option « charger sans ouvrir » : impossible de précharger le niveau suivant pendant le jeu pour l'ouvrir plus tard, ni de passer des paramètres à la scène chargée (utiliser un autoload pour transmettre l'état).
  • loading_progress à chaque image, même sans changement de valeur, et la progression de Godot avance par paliers (souvent 0 puis 100 pour une petite scène).
  • Gestionnaire placé dans la scène remplacée : il est détruit avec elle et load_finished n'est jamais émis.
  • Le changement de scène lui-même reste synchrone : l'instanciation du niveau et les _ready de ses nœuds se font sur le fil principal, ce qui peut encore provoquer un court gel sur une très grosse scène.

🏗️ Architecture

Composants et communication

  • SceneManager est un Node singleton. load_scene_async envoie une requête à ResourceLoader et active _process, qui sonde l'état à chaque image et émet loading_progress. Une fois la scène chargée, il appelle change_scene_to_packed en différé ; il écoute SceneTree.scene_changed et n'émet load_finished que pour un changement qu'il a lui-même demandé.
  • Le _process est désactivé hors chargement : aucun coût le reste du temps.

Dépendances et couplage

  • → ManagerBuilder (bibliothèque tool_editor) : optionnel, par ClassDB.
  • → journal log_it (module 📰 Journal Console) : fonction inline d'un header, compilée dans cette bibliothèque ; aucune bibliothèque à installer.
  • Aucun module ne dépend du gestionnaire. Bibliothèque propre : scene_manager_register.cpp → bin/scene_manager/.

Décisions de conception

ChoixPourquoi (ne pas « corriger » sans en tenir compte)
Changement de scène différé (call_deferred)Changer de scène au milieu du _process peut détruire des nœuds en cours de traitement.
load_finished sur scene_changed, pas juste après l'appelLe signal arrive quand la nouvelle scène est réellement en place : on peut y chercher ses nœuds.
Indicateur « changement attendu »Un change_scene_to_file fait ailleurs ne doit pas conclure un chargement en cours.
Récupération du résultat même en cas d'échecSans load_threaded_get, la tâche échouée resterait en mémoire jusqu'à la fermeture du jeu.
Une requête à la foisDeux chargements concurrents se disputeraient la scène courante ; la première demande l'emporte.
Singleton via ManagerBuilder, doublons détruitsUn seul gestionnaire écoute scene_changed : pas de double load_finished si un autoload et un nœud de scène coexistent.
