📰_LogSystem - Édition et Debug - Documentation

Module Journal Console : des messages de console horodatés, signés par leur émetteur et mis en forme.

Godot 4.7+ Bibliothèque bin/tool_editor 1 classe : L GDScript & C++

📝 Présentation

Avec print(), la console devient vite un mur de lignes anonymes : impossible de savoir quand un message a été écrit ni quel objet l'a écrit, et tout a la même couleur. Ce module donne à chaque message une heure, un émetteur et, au besoin, une icône et des couleurs, en un seul appel : L.log_it("Porte ouverte", self).

🕒 Horodaté et signé

Chaque ligne commence par [hh:mm:ss] en gris, puis le nom du nœud (ou de la classe, ou du texte) qui l'émet, en gras.

🎨 BBCode et icône

Le message accepte le BBCode de print_rich (couleurs, gras, liens) ; une petite image peut identifier le système émetteur dans le panneau Sortie.

Pour qui ? Tout développeur du projet qui veut une console lisible pendant le debug. Les autres modules du toolkit (sauvegarde, gestionnaire de scènes, fenêtre d'édition…) écrivent déjà leurs messages avec ce format, côté C++.

Ce que ce module n'est pas
  • Pas un système de journalisation complet : pas de niveaux (info / avertissement / erreur), pas de filtre, pas d'écriture dans un fichier dédié, pas de désactivation en version exportée.
  • Pas un remplaçant de push_error / push_warning : ces messages n'apparaissent pas dans l'onglet Débogueur › Erreurs et ne donnent pas de pile d'appels.
📷 Image à insérer
Capture du panneau Sortie de l'éditeur montrant trois lignes : un message simple, un message avec nom de nœud en gras et une icône 16 px, un message en rouge ; à côté, la même chose écrite avec print() pour comparer.

🛠️ Installation

Dépendances

DépendanceNaturePourquoi
Godot 4.7 ou plus récentObligatoireLa bibliothèque déclare compatibility_minimum = "4.7" : une version antérieure refuse de la charger.
Bibliothèque bin/tool_editor/ (gameplaytoolkit_tool_editor.gdextension + binaires)Obligatoire pour GDScriptElle enregistre la classe L. Elle contient aussi tous les autres outils d'édition et de debug (gizmos, éditeur d'objet…) : on ne peut pas installer L seule.
Images d'icônes (res://…png)OptionnelleUniquement si vous passez un icon_path.

Côté C++, un autre module du toolkit n'a besoin d'aucune bibliothèque : la fonction log_it est entièrement définie dans custom_logger.hpp, il suffit de l'inclure.

Mise en place

  1. Compiler la bibliothèque (si les binaires ne sont pas déjà présents) depuis la racine du dépôt : 
    scons tool_editor
    compile uniquement la bibliothèque des outils d'édition (tool_editor_register.cpp) et régénère son .gdextension.
  2. Copier le dossier bin/tool_editor/ dans le projet Godot, au même emplacement : res://bin/tool_editor/.
    le .gdextension référence ses binaires par des chemins res://bin/tool_editor/… ; ailleurs, Godot ne les trouve pas.
  3. Redémarrer l'éditeur après le premier ajout.
    Godot ne découvre les nouvelles extensions qu'au démarrage ; la console affiche alors « 🛠️Module d'outils d'edition et de debug chargé avec succès ! ».

Aucun autoload, nœud ni réglage de projet : L est une classe statique, utilisable immédiatement dans n'importe quel script.

⚙️ Mode d'emploi

  1. Remplacer un print par L.log_it : 
    L.log_it("Partie chargée")
# [14:02:31] Partie chargée
    l'heure (horloge du système, à la seconde) permet de situer le message par rapport aux autres.
  2. Signer le message en passant l'émetteur en deuxième argument : 
    L.log_it("Porte ouverte", self)          # nom du nœud, ex. « Porte »
L.log_it("Sauvegarde écrite", "SaveSystem") # texte libre
    quand plusieurs objets écrivent dans la console, le nom en gras dit immédiatement d'où vient la ligne.
  3. Colorer et illustrer avec du BBCode et une icône : 
    L.log_it("[color=red]Coffre verrouillé[/color]", self, "res://icones/cadenas_16.png")
    le rouge attire l'œil sur les problèmes ; l'icône identifie un système d'un coup d'œil. Utiliser une image déjà petite (16 px) : elle est affichée à sa taille d'origine.

💻 API Accessible

Référence générée depuis doc_classes/L.xml. Éléments internes, non exposés à GDScript :

  • La fonction C++ libre godot::log_it(message, object_caller, icon_path) de custom_logger.hpp, qui fait le vrai travail et que les autres modules C++ appellent directement.

📌 Exemples d'utilisation

Comment je donne une identité visuelle à un de mes systèmes ?

Une constante pour l'icône et une petite fonction : tous les messages du système auront le même en-tête.

extends Node

const ICONE := "res://icones/inventaire_16.png"

func journal(message: String) -> void:
	L.log_it(message, "Inventaire", ICONE)

func ajouter(objet: String) -> void:
	journal("[color=green]+ %s[/color]" % objet)

Comment je signe un message émis par une ressource ?

Pour un objet qui n'est pas un nœud, c'est le nom de sa classe native qui s'affiche (Resource, et non le class_name du script). Passer plutôt un texte :

class_name Arme extends Resource

@export var nom := "Épée"

func casser() -> void:
	L.log_it("[color=orange]%s cassée[/color]" % nom, "Arme")  # et non `self`, qui afficherait « Resource »

Comment je rends un message cliquable ?

Le BBCode [url] est accepté par print_rich : dans le panneau Sortie, le lien est cliquable.

L.log_it("Voir la [url=https://docs.godotengine.org]documentation[/url]", "Aide")

Comment je n'affiche mes messages qu'en version de développement ?

L.log_it écrit toujours, même dans un jeu exporté. Filtrer soi-même :

func trace(message: String, emetteur = null) -> void:
	if OS.is_debug_build():
		L.log_it(message, emetteur)

🚧 Limitations

  • Aucun niveau ni filtre. Tous les messages sont affichés, y compris en export release. Pas d'équivalent de push_warning : rien n'apparaît dans l'onglet Erreurs du débogueur.
  • Précision à la seconde. L'heure vient de l'horloge du système (Time.get_time_dict_from_system) : deux messages de la même frame ou de frames proches ont la même heure ; pas de millisecondes ni de numéro de frame.
  • Émetteur : seuls les nœuds, objets et textes sont reconnus. Un objet non-nœud affiche le nom de sa classe native (un script class_name Arme extends Resource affiche « Resource »). Un nombre ou tout autre type est silencieusement ignoré.
  • L'icône est affichée à sa taille d'origine (la balise [img] est générée sans taille). Une image de 512 px occupe tout le panneau : préparer des icônes de 16 px.
  • Hors de l'éditeur, l'icône s'affiche en clair. Dans un terminal (jeu lancé en console, --headless), les couleurs deviennent des codes ANSI mais la balise [img]res://…[/img] est imprimée telle quelle (vérifié en headless).
  • Le BBCode n'est pas échappé. Un texte venant du joueur qui contient [ peut être interprété comme une balise ; le nom d'un nœud est aussi inséré tel quel.
  • L dérive d'Object : L.new() crée un objet inutile qu'il faudrait libérer à la main. N'utiliser que l'appel statique.

🏗️ Architecture

Composants et communication

  • godot::log_it (fonction inline de custom_logger.hpp) construit la ligne — heure grisée, émetteur en gras, icône, séparateur : seulement s'il y a un émetteur ou une icône — puis appelle print_line_rich.
  • L est une coquille : sa méthode statique log_it délègue à la fonction ci-dessus. Les valeurs par défaut sont redéclarées dans _bind_methods (DEFVAL) pour que GDScript puisse appeler L.log_it("message") seul.
  • Appel direct, sans état, sans signal ni singleton.

Dépendances et couplage

  • Le module ne dépend d'aucune autre classe du toolkit.
  • Il est utilisé, en C++, par 💾 Système de Sauvegarde, 🎬 Gestionnaire de scènes, 🪟 Fenêtre d'édition et l'éditeur d'objet : comme la fonction est dans le header, ces modules n'ont pas besoin que bin/tool_editor/ soit installée.

Décisions de conception

ChoixPourquoi (ne pas « corriger » sans en tenir compte)
Fonction inline dans le header plutôt que méthode compilée dans tool_editorChaque bibliothèque du toolkit est indépendante : un module ne peut pas appeler du code compilé dans une autre. Le header permet à tous d'avoir le même format sans dépendance de lien.
Nom de classe d'une seule lettre, LAppel aussi court que print, pour qu'il soit adopté partout.
Méthode nommée log_it, pas loglog est déjà une fonction globale de GDScript (logarithme) : le nom était source de confusion. Changement cassant (voir changelog).
Nœud → son nom, autre objet → sa classeDans une scène, plusieurs nœuds de même classe coexistent : le nom les distingue. Une ressource n'a pas de nom fiable.
